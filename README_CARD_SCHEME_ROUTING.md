# Маршрутизация адаптеров по платёжной системе карты

Добавлено правило маршрутизации банковских карт по BIN/IIN — первым цифрам номера карты.

## Правила

- МИР (`2200–2204`) → `YooKassaAdapter`
- Visa (`4`) → `StripeAdapter`
- Mastercard (`51–55`, `2221–2720`) → `StripeAdapter`
- Неизвестная карта → обычная маршрутизация через `merchant_payment_routes` или fallback

## Что изменено

Файлы:

```text
internal/orchestrator/simple/card_scheme.go
internal/orchestrator/simple/router.go
web/index.html

```

## Как проверить

1. Запусти шлюз с ключами ЮKassa и Stripe.
2. Открой фронтенд.
3. Выбери способ оплаты `Банковская карта`.
4. Введи номер карты.
5. Под полем номера карты появится подсказка:

```text
Платёжная система карты: МИР. Провайдер: ЮKassa.
```

или:

```text
Платёжная система карты: Visa. Провайдер: Stripe.
```

Примеры тестовых номеров, проходящих проверку Луна:

```text
МИР:        2200000000000004
Visa:       4242424242424242
Mastercard: 5555555555554444
```

## Важно

Это учебная упрощённая BIN/IIN-маршрутизация. Для промышленного платёжного шлюза нужна полноценная BIN-база, потому что по BIN/IIN обычно определяют не только платёжную систему, но и банк-эмитент, страну, тип карты и другие параметры.

## Почему router.go остаётся в orchestrator/simple

Файл `internal/orchestrator/simple/router.go` — это не отдельная подсистема. Это файл с реализацией контейнера `Маршрутизатор платежей`, который является частью оркестратора платежей. Файл вынесен отдельно только для чистоты кода, чтобы не хранить всю логику оркестратора в одном большом `orchestrator.go`.
